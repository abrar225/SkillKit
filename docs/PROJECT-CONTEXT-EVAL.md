# Which optional features earned a place?

The same three mobile briefs were submitted with no project information, then with local manifests from Flutter, React Native, and Swift fixtures. A useful stack match required a ready implementation stage, a matching reference, and no competing stack-specific selection. The table counts nine brief/project pairs. These small synthetic fixtures measure routing only.

| Endpoint | Without project | With project | Wins / ties / losses |
| --- | --- | --- | --- |
| Correct stack-specific skill | 0/9 | 2/9 | 2 / 7 / 0 |
| Correct stack-specific skill or official reference | 0/9 | 4/9 | 4 / 5 / 0 |

All three empty-project controls returned identical kits. The fixture code and results are in bench/project-context.mjs and bench/project-context-results.json. Reproduce with `node bench/project-context.mjs`. Provide `--project <directory>` to the local CLI when the task depends on the project’s technology. The server never reads a caller-supplied filesystem path.

Match explanations expose the coverage decision and a skill-gap brief. Persona checklists can be used by the receiving agent. Outcome data stays opt-in and out of the rankings. A learned reranker, autonomous verification of arbitrary user output, and automatic publication of new skills lack a demonstrated gain in this trial.
